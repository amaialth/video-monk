## Candidate visual techniques

- Stable endpoint cards beside separate header/account-version badges. Use
  labels and arrows so a date is not mistaken for a release date or URL version.
- A persistent three-lane diagram: incoming request transformation, current
  core representation and outgoing response transformation. Keep arrow direction
  and example data consistent across the sequence.
- Before/after payloads with aligned field names, restrained highlights and
  readable holds. Show a small original example instead of copying source code.
- A dated transformation chain with explicit direction and a visible target
  schema. Separate conceptual steps from verified implementation details.
- A trade-off summary that balances developer stability against internal testing,
  maintenance and migration costs, rather than promising cost-free compatibility.
