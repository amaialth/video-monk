# Optional original graphic recipes

Load only the recipe needed for the storyboard. These are manual implementation
options, not measured ByteMonk production methods or applied CLI effects.
Check the installed Resolve edition/version and exact controls before using them.

## Shared design kit

Prototype a short original narration/diagram segment first. Use a dark neutral
canvas, readable heading/body/code hierarchy and restrained accents with labels
or icons. Check text contrast and safe areas at final size and on a small display.
Do not assume exact source hex values/fonts or copy creator branding.

### Cards and borders

Mask a Background with a rounded Rectangle and composite with Merge; add Text+.
Use a separate border mask and optional blurred duplicate for a restrained glow.
Check the exact glow node/effect's availability; similar Fusion/Resolve FX names
are not interchangeable. Avoid bloom that damages small-text readability.

### Progressive diagrams and lanes

Reveal nodes/edges via mask, opacity or position keys, with Spline easing.
Animate a small ellipse along an original path for illustrative dataflow;
particles are optional, not necessary. Keep actors/lanes stable and labels explicit.
Timing follows explanation, not a fixed cut clock. Node-specific mask/write-on
controls must be checked, not assumed universal.

### Maps and hexagonal boundaries

Use original/licensed map art and synthetic nonprivate coordinates. Animate
markers along a route. Create hexagons with an actual six-vertex Polygon mask or
original vector art; a rounded Rectangle is not a hexagon. Start with a legible
2D grid instead of assuming a 3D globe is necessary. Distinguish raw/smoothed
illustrative paths from telemetry or a validated filter output.

### Tables, code and schemas

Align rows/columns or original before/after payloads; keep headings visible.
Reveal only the branch, field or row currently explained. Split dense tables
rather than shrink text. Maintain request/response direction and explicit
version labels through schema transformations. Diagrams don't validate code.

### Execution states and comparisons

Stack original function cards with a top-of-stack marker; animate push/pop with
position/opacity keys. Keep source/bytecode/native or main-thread/OS/pool lanes
spatially stable, with labeled submission, completion and fallback paths.
Give code and output enough reading time; label simulated traces. A color pulse
does not prove optimization, latency, message delivery or execution order.

### Sources, timelines and charts

Animate a timeline marker along a labeled axis. For permitted source artwork,
use a masked translucent highlight without hiding publisher/date or quote context.
For original charts, retain data values, units, axes, time range and source
throughout a mask/path reveal. Align comparison scales and disclose log/truncated
axes. Separate misconception/reality panels with explicit headings. Particle or
equation imagery is illustrative unless independently validated.

### Long-form captures

Use original recordings, chapter cards and manual timeline markers. Crop
terminal/browser captures without hiding command context. Show prerequisite,
action and actual result checkpoints; disclose jump cuts, accelerated waits and
omitted output. Label destructive operations without running reference commands.
A montage is not evidence of an uninterrupted successful lab.

## Audio and color

Mix original dialogue with licensed music/SFX. Align sparse cues to meaningful
state changes. Use manual Fairlight level automation if ducking availability is
unknown; listen and measure before choosing EQ/compression/limiting. A gate
doesn't remove reverb and better recording is not equivalent to AI isolation.
Keep semantic graphic accents separate from footage color-management/grading.
Check input spaces, match shots with scopes and review actual output.

These recipes do not enable Studio-only features, make an effect equivalent to
another, execute demonstration code or create a final render automatically.
