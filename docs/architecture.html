How Video Monk works

Video Monk turns a recording into a finished explainer video: it cuts the dead air, adds captions, plans and animates graphics that explain what you say, mixes and masters the sound, and checks its own work at every step. Everything runs on your computer except two optional steps that use Claude.

New here? Read What's new and The big picture first (5 minutes). The rest of the page is reference: each part in detail, in the order it runs.

Three releases turned a rough-cut helper into an automated editor that explains, checks itself and remembers what it made. Full list: CHANGELOG.md.

  • The slide stays visible beside a panel. The picture eases down next to the panel and back, instead of being covered. --fit contain shows the whole frame for slides in vertical videos.
  • Reviewer check: the cut reviewer flags zoom flicker and the reviser removes it.

Overview

Video Monk has no npm dependencies. It orchestrates three local tools (FFmpeg, headless Google Chrome and whisper.cpp) and keeps every step checkable.

Local and private

Transcription runs on your machine. Graphics render offline in headless Chrome with DNS blocked. Nothing is uploaded unless you opt in to a stock search or an LLM call.

Deterministic

Every graphic is a pure function of time, seek(t). The same manifest always yields the same frames, so renders are reproducible and frame exact.

Gated

A build only runs if the plan review approved the exact manifest, media and caption hashes. Rights, facts and publishing stay human decisions.

Verified

The final file is decoded, then measured for size, frame rate, duration, integrated loudness and true peak before it is reported as passing.

System architecture

Everything runs through one CLI. Modules fall into three groups, each backed by an external tool. FFmpeg is the foundation under all of them.

The one-shot pipeline: auto

One command runs the four stages, each under its review loop, and writes everything into a new folder.

video-monk auto --media talk.mp4 --output talk-v1 --transcribe \
  --allow-render --approve-plan --rights-confirmed

Inspect

Measures duration, size, fps, loudness, true peak and pauses; writes analysis.json with suggestions.

Transcript

Local whisper.cpp words with times, refined against measured silences. Reused from the library when the same recording was transcribed before.

Cut

Measures your noise floor, removes pauses, breaths, hums and filler words, trims quiet edges, adds punch-ins, remaps captions, writes a version-2 manifest.

Storyboard

Plans graphics from the transcript in the house style and writes STORYBOARD.md plus an editable storyboard.json.

Render

Approves the plan by content hash, renders (reusing library graphics), mixes, masters, verifies the real file and writes every deliverable.

After each of the last four stages a reviewer approves or rejects, and the maker fixes only what was flagged (see Review loops). If a stage is still rejected after 3 rounds, auto stops with needs-human and lists what is open.

How autocut decides what to keep

The planning step (planCuts) is a pure, unit-tested function. It turns measurements and words into frame-aligned ranges.

Pace presets and speed

The silence threshold is measured from the recording itself: a 20 ms level histogram has a noise-floor peak and a speech peak, and the valley between them (Otsu split, clamped −48 to −30 dB) becomes the threshold. Sounds that stay below speech level for 0.3 s (breaths, hums, mouth noise) are cut as quiet stretches, and quiet lead-ins and tails are trimmed from each kept segment, only when they last long enough not to be soft consonants.

PresetThresholdMin pausePaddingUse
natural−35 dB fixed0.35 s0.08 / 0.14 sGentle, relaxed delivery
tight (default)measured0.15 s0.05 / 0.08 sExplainers and tutorials
extrameasured + 2 dB0.10 s0.04 / 0.06 sFast-paced shorts (may nick soft word endings)

--speed 1.1 to 1.5 speeds speech up with pitch preserved; captions and cues are retimed. Other tuning: --noise-db, --min-silence, --keep-fillers, --no-jump-zoom, and --format vertical|landscape|square. Whisper rarely transcribes "hm", so those sounds are removed acoustically rather than by name.

Review loops

Every stage has a producer and an independent reviewer. A reviewer rejects with structured findings; the producer fixes only what was flagged; a lead loop sends feedback to the stage that owns the problem.

Example finding: cut-quiet-12-33.20, major, owner cut, target scene 12 at 33.2–33.5 s, fix removeQuiet. The cut reviser splits only that segment, rebuilds the manifest and remapped captions, and the reviewer re-checks. On a real quiet recording the check showed 100% of clearly voiced audio kept after tightening.

Asset library

Generated and licensed assets are indexed once and found everywhere. Default root ~/.video-monk/library.

Graphics

Rendered frames are cached by content hash in the library and indexed with template, text, size and theme. An identical graphic in another project is not rendered again.

Transcripts

Keyed by media hash, model, language and prompt. The same recording is never transcribed twice.

Storyboards

A Claude storyboard for the same transcript and settings is reused, so the paid call does not repeat.

Licensed assets

Music, SFX, images and fonts with rights, attribution and source URL recorded once; checked out with a ready manifest entry. Never auto-approved, never pruned.

Commands: assets --search, --add, --get, --export (cached graphic to .mov alpha / .mp4 / .png), --stats, --prune. The librarian agent searches before anything is generated or downloaded.

House style

Every video follows one look unless you say otherwise. It is a creative direction taken from your ByteMonk study notes, not a verified description of the channel, and it never copies the channel's wording, branding or sponsor material.

AspectWhat the style does
Canvas and colourDark neutral background, rounded cards, one cyan accent plus a semantic palette. Colour is always paired with an icon or text.
MotionCalm: smooth reveals with no overshoot, nodes and steps appear as the narration names them, no gratuitous transitions.
GraphicsDiagrams first. Flows, steps, comparisons, definitions and chapter cards are favoured; pull-text is capped at a quarter of the graphics.
HonestyConceptual diagrams are labelled “Conceptual schematic”. No invented numbers.
PaceTight cuts of dead air, but no fixed cutting formula; an idea is held until it is understood.
AudioNarration first; a restrained licensed ambient bed ducked 14 dB under speech.

Switch with --style plain. A manifest's own theme settings always win over the style. The Claude planner receives the style as part of its brief, and the storyboard reviewer checks pull-text share against it.

The explainer graphics planner

This is what makes the edit explain things instead of only cutting them. It reads the timed transcript, finds ideas that can be shown, and places graphics on the timeline under rules that protect the speaker.

Cutaway, panel or overlay

Split layout. A side panel does not cover the picture. While it is up, the video eases down to about 47% of the frame width beside the panel, on the theme background, and expands back when the panel leaves, so the content being explained stays fully visible. No camera zoom runs under any graphic, and the per-cut zoom is off by default (--jump-zoom holds each zoom for at least 8 s). Manifest overlays use layout: "split" with placement left or right.

Cutaway

Opaque full frame for a diagram or card that deserves 3–8 seconds. Audio keeps playing. Needs two seconds of speaker or slide between cutaways.

Panel

A box on the right half that ends above the captions. Long ideas (up to 26 s) become panels, and the picture shrinks beside it so the slide stays fully visible.

Overlay

A short pull-text strip at the top of the frame for a key phrase, question or claim.

Nothing

Greetings, personal remarks and anything that would only restate the caption get no graphic.

Grounding and cues

Every label, number and phrase comes from the transcript, and numbers are used only when the speaker said them. Items such as bullets, steps, flow nodes, bars and pull-text words carry cues: the spoken time of the word that names them, so each element appears as the word is said. With the Claude engine the model names the cue words and the tool aligns them to the real word timestamps.

Method credits

Density levels, the cutaway-or-panel-or-nothing decision, minimum face time and the never-invent-numbers rule follow the motion-graphics skill by Barty-Bart (MIT). The structure of the Claude brief (inputs, direction, structure, rules, output) reflects craft lessons from the creator-prompt collection awesome-opus-5-5-video-prompts; no prompt text from it is copied because those prompts belong to their authors. See THIRD_PARTY_NOTICES.md.

Kinetic typography

All text uses one system, from the kinetic-typography skill by iart.ai (MIT): a strong sans for the line and a different face for the words that carry the point.

Two faces

Geist Variable (weights 100–900) for lines. Instrument Serif Italic, 1.16× size in the accent colour, for stressed words. Both bundled under the SIL OFL.

Stress markup

Write *word* in any headline-style prop. Captions choose stress automatically from numbers, acronyms, proper terms, intensifiers, lingered-on words and pauses.

Reveals

Words rise from a hidden baseline with expo-out easing and 40–70 ms stagger. Stressed words also focus-pull from blur to sharp. Reveal styles: mask, blur, pop.

Captions

The kinetic style keeps bold sans, pops the word being spoken in the accent colour and sets stress words in italic serif. Rendered in ~40 s chunks in parallel.

Themes

night or paper (warm gray, black ink, one orange accent). auto picks by footage brightness.

The motion engine

Each graphic is a self-contained HTML page. Headless Chrome seeks it to every frame time and captures a PNG. FFmpeg later layers those PNGs over video.

Safety properties

No network

Chrome starts with --host-resolver-rules=MAP * ~NOTFOUND. Pages cannot reach the internet.

No script injection

Props are JSON-escaped, text is set with textContent, and the schema rejects control characters and unknown fields.

Fresh profile

Each run uses a temporary profile with extensions, sync and background networking disabled, and it is deleted afterwards.

Custom HTML is trusted code

Your own html page runs in the same sandboxed Chrome, but review it before approving. Its bytes are part of the fingerprint.

Placement and theme

Full-screen graphics fill the frame. Overlays use one of twelve placements: full center left right top bottom top-left top-right bottom-left bottom-right strip-top strip-center (boxed placements end above the caption zone). In portrait, left/right become the top/bottom halves. Boxed overlays get a translucent panel. lower-third, callout, progress-bar and captions always use the full frame. The manifest theme takes a preset (night or paper), optional token overrides (background surface text muted accent), a chart palette and a font file.

Timeline arithmetic

Transitions overlap neighbouring scenes, so total duration is the sum of scene durations minus the sum of transition durations. A transition must be shorter than both scenes it joins, and the last scene cannot have one. Narration longer than the timeline is rejected rather than silently truncated.

Transitions and camera moves

Transitions (25): fade, fadeblack, fadewhite, dissolve, wipeleft/right/up/down, slideleft/right/up/down, smoothleft/right/up/down, circleopen, circleclose, radial, pixelize, zoomin, distance, hblur, squeezeh, squeezev. Camera: zoom-in, zoom-out, pan-left/right/up/down (cosine-eased zoompan on a 2× canvas) and punch-in (a static crop).

The build pipeline

production-build runs eight stages. Intermediate work lives in work/, and motion frames are deleted after a successful build unless you pass --keep-work.

Gate

Reload the manifest, recompute the fingerprint and require it to equal the approved review. Create the output folder only after this passes.

Motion frames

Render every graphic and the caption layer in headless Chrome in parallel. Frames live in the asset library, so an identical graphic from any earlier project is reused instead of rendered.

Scene composites

For each scene: fit or reframe the source, apply camera motion, overlay B-roll, then overlay motion PNGs in 4:4:4. Encode an intermediate and cut matching source-audio clips.

Join

Hard-cut runs are stream-copied together. Scenes separated by transitions are joined with xfade at frame-exact offsets.

Audio mix

Build voice, music and SFX buses, duck the music under speech and write stems.

Mastering

Two-pass gain to the loudness target with an oversampled peak limiter, written to stems/master.wav. The video is encoded once; audio is muxed separately, so a fix costs seconds.

Final encode

One pass applies transitions, overlays and captions. The master is muxed as AAC, then the decoded file is measured: if AAC overshot the true-peak limit, only the offending 10 ms windows get a brief gain dip and the file is re-muxed.

Deliver and verify

Write captions, chapters, thumbnail, contact sheet, Resolve XML and credits. Decode final.mp4 and measure size, fps, duration, LUFS and true peak.

--quality draft uses faster x264 settings for quick iterations; final (default) uses the manifest's crf and preset.

The audio graph

Speech always wins. Music is compressed against the voice with a sidechain, and the result is mastered to the target loudness.

Approval gates and verification

The toolkit separates what it can prove (structure, hashes, decoded media, measured levels) from what only a person can decide (facts, rights, taste).

Automatically checkedAlways left to a human
Manifest schema, frame alignment, source bounds, template props, narration fit, hashes, decode, dimensions, fps, duration, loudness, true peak, caption presence.Factual accuracy, chart values, caption wording, asset rights and attribution, creative quality, whole-video playback and publication.

Reports carry explicit NOT VERIFIED and USER ATTESTED markers, and the build never reports a file as final. production-verify re-runs the technical checks on any file you export elsewhere.

Testing

npm test runs 108 tests. Real-render tests run when FFmpeg and Chrome are installed.

  • Unit: caption paging and remapping, cut planning, silence refinement, whisper JSON parsing, template schema validation, placement maths.
  • Timeline: 12 rejection cases (bad template, overlay out of bounds, transition too long, unaligned durations, missing captions file, unapproved asset and others).
  • Gating: a build is refused without a matching approval.
  • End to end: a real run with autocut, a counting-up stat scene, a transition, an overlay chart, captions, ducked music and mastering, checking every deliverable and that the animation changes over time.
  • Customization: installed skills and agents keep their tool boundaries, valid links and size budgets.

Limits

  • Transcripts are drafts. Proofread names, numbers and jargon before publishing captions.
  • Charts show the numbers you give them; the toolkit checks structure, not truth.
  • Silence detection is acoustic. Background music or a noisy room may need --noise-db tuning, and cuts should be watched.
  • auto plans graphics by default (offline rules). For richer diagrams use --engine claude --allow-llm or have Claude edit the storyboard.
  • Each command takes one recording. Folder or batch input is not built yet.
  • Reviewers catch what can be measured (silence, lost speech, invented numbers, overlaps, loudness, black frames). Taste, facts and rights still need a person, and a finding they cannot fix stops the run for you.
  • Whisper does not transcribe “hm” or “um” for many speakers, so those sounds are removed as low-level stretches, not by name.
  • Split layouts are filtered and scaled separately, so renders with many panels take longer (about 100 s more on a 6-minute 1080p60 video).
  • The asset library grows (rendered frames are PNG sequences). Check assets --stats and prune with assets --prune --older-than-days N --yes. Licensed assets you add are never pruned.
  • The offline planner works from patterns in the words; on conversational speech it mostly yields pull-text and a few definition cards, lists and flows. The Claude engine (opt-in, sends the transcript to Anthropic) draws real diagrams. Always review the storyboard.
  • Rights, attribution, factual accuracy and publishing are always human decisions.
